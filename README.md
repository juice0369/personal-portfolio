# 个人数字作品集与内容管理网站

一个纯前端的个人作品集站点：访客看到的是深色风格的作品集页面，站点所有者可以在浏览器里的 `/admin` 后台直接维护内容，改完即时生效。

全部数据都在浏览器本地读写，不连接任何后端服务、数据库或云端存储，构建产物是一组静态文件，可直接托管到 Cloudflare Pages。

> **演示声明**：后台登录是**课程演示登录**，不是生产级身份验证。账号密码以常量形式写在
> `src/lib/constants.ts` 中，任何人查看构建产物都能读到；登录状态只用于区分"是否显示后台页面"，
> 不构成安全边界，无法阻止他人通过开发者工具直接改动本地数据。请**不要**在这里存放真实敏感信息。

---

## 1. 技术栈

| 层       | 选型                                                                   |
| -------- | ---------------------------------------------------------------------- |
| 构建工具 | Vite 8                                                                 |
| 界面框架 | React 19 + TypeScript（`strict`）                                      |
| 路由     | React Router 8（`createBrowserRouter`，页面全部懒加载）                |
| 样式     | Tailwind CSS 4（`@tailwindcss/vite`，设计令牌定义在 `src/index.css`）  |
| 校验     | Zod 4（schema 是数据类型的唯一来源，类型由 `z.infer` 推导）            |
| Markdown | `react-markdown` + `remark-gfm` + `rehype-sanitize`                    |
| 本地存储 | `localStorage`（内容数据）+ `IndexedDB`（头像与简历，经 `idb-keyval`） |
| 测试     | Vitest + Testing Library + `fake-indexeddb`                            |

不使用后端语言、服务端运行时、数据库、ORM、云存储与 CDN 资源。

## 2. 环境要求与启动

需要 Node.js `^20.19.0` 或 `>=22.12.0`（仓库 `.nvmrc` 记录 `24`）。

```bash
npm install     # 安装依赖
npm run dev     # 启动开发服务器，默认 http://localhost:5173
```

首次打开时，页面展示的是随源码提供的内置默认数据（本人的姓名、公开邮箱、公开主页与教育/项目经历，内置简历为本人的简历 PDF），无需任何配置。

### 可用脚本

| 命令                   | 作用                                                                     |
| ---------------------- | ------------------------------------------------------------------------ |
| `npm run dev`          | 启动开发服务器                                                           |
| `npm run build`        | 类型检查 + 生产构建，产物输出到 `dist/`                                  |
| `npm run preview`      | 本地预览生产产物（不读取 `_headers`，也不复现 Pages 的 SPA 回落，见 §7） |
| `npm run typecheck`    | TypeScript 类型检查                                                      |
| `npm run lint`         | ESLint（含 `react-hooks` 与 `jsx-a11y` 规则）                            |
| `npm run lint:fix`     | ESLint 自动修复                                                          |
| `npm run format`       | Prettier 格式化                                                          |
| `npm run format:check` | Prettier 检查（不写入）                                                  |
| `npm run test`         | Vitest 单次运行                                                          |
| `npm run test:watch`   | Vitest 监听模式                                                          |

## 4. 页面与路由

### 前台

| 路径              | 页面                                                                                                                 |
| ----------------- | -------------------------------------------------------------------------------------------------------------------- |
| `/`               | 首页单页：`#profile` 个人介绍、`#skills` 技能分类、`#timeline` 经历时间线、`#projects` 精选项目、`#contact` 联系方式 |
| `/projects`       | 项目列表（按分类筛选）                                                                                               |
| `/projects/:slug` | 项目详情（背景、职责、技术栈、成果要点、Markdown 正文、外链）                                                        |
| `/blog`           | 博客列表（标签筛选、分页，查询参数 `?tag=`、`?page=`）                                                               |
| `/blog/:slug`     | 博客详情（Markdown 正文、上一篇 / 下一篇）                                                                           |
| 其他              | 404 页面                                                                                                             |

简历下载入口在首页首屏、页脚与移动端抽屉导航中，下载的是管理员上传的 PDF；未上传时回落到内置简历。

### 后台（统一在 `/admin` 下）

| 路径                    | 页面                                                   |
| ----------------------- | ------------------------------------------------------ |
| `/admin/login`          | 演示登录（独立全屏布局）                               |
| `/admin`                | 数据统计仪表盘                                         |
| `/admin/profile`        | 个人信息管理：资料表单、头像上传预览、经历时间线增删改 |
| `/admin/skills`         | 技能与分类的增删改、排序与熟练度                       |
| `/admin/projects`       | 项目增删改（抽屉表单，含 Markdown 正文）               |
| `/admin/posts`          | 文章列表                                               |
| `/admin/posts/new`      | 新建文章（整页 Markdown 编辑器 + 实时预览）            |
| `/admin/posts/:id/edit` | 编辑文章                                               |
| `/admin/settings`       | 站点设置、简历文件管理、数据导出 / 导入 / 恢复默认     |

进入后台的页面都经过 `RequireAuth` 守卫；未登录时会重定向到登录页，并在 `redirect` 参数里
记录原目标地址。回跳地址只接受以 `/admin` 开头的站内路径，外站地址会被拒绝。

## 5. 功能说明

### 前台

- 个人介绍、技能分类、经历时间线（结束时间为空显示为"至今"）、精选项目、联系方式与响应式导航栏 / 页脚。
- 项目列表与详情、博客列表与详情；草稿文章不会出现在前台，直接访问草稿地址显示未找到页面。
- 简历下载：优先使用管理员上传的 PDF，未上传时使用内置简历（`public/resume-sample.pdf`，本人简历，随仓库发布）。
- 深色视觉：深炭黑背景 `#0B0B0D`、米白文字 `#F5F1E8`、香槟金强调色 `#C9A96A`，无蓝紫渐变。
- 轻量星空背景：纯 CSS 静态渐变与星点，不接收鼠标事件、对屏幕阅读器隐藏；可在站点设置中关闭，也会在开启"减少动态效果"时停用。

### 后台

- 个人信息、头像、简历、技能、项目、博客、站点设置的完整增删改。
- 所有删除操作都有二次确认，确认按钮写明具体后果，并在提示中提供一次性撤销入口。
- 表单基于 Zod 校验，错误提示定位到具体字段并说明约束（例如"项目标题不能超过 60 个字符"）。
- 高频输入（Markdown 正文）使用组件本地状态，保存时才写入全局状态，避免逐字写存储造成卡顿。
- 后台保存后，同标签页导航到前台即显示新内容，不需要刷新；其他标签页通过 `storage` 事件同步。

## 6. 数据存储与备份

| 内容                                             | 位置             | 键 / 库名                            |
| ------------------------------------------------ | ---------------- | ------------------------------------ |
| 结构化内容（资料、技能、经历、项目、文章、设置） | `localStorage`   | `portfolio:content:v1`               |
| 登录会话标记                                     | `sessionStorage` | `portfolio:auth:v1`                  |
| 头像与简历的二进制文件                           | `IndexedDB`      | 库 `portfolio-assets`，存储 `assets` |

数据来源分三层，优先级从高到低：`localStorage` 中的本地修改 → 内置默认数据（`src/data/`）→
二进制文件缺省时回落到 `/default-avatar.jpg` 与 `/resume-sample.pdf`（内置简历，见 §5）。本地数据结构不合法时
（被手动篡改或版本不匹配），整份数据回落为内置默认数据并给出提示。

`/admin/settings` 的"数据"面板提供：

- **导出 JSON**：导出当前内容数据，含版本号与导出时间。**不含**头像与简历的二进制文件。
- **导入 JSON**：先校验体积（≤ 2MB）与结构，再展示与当前数据的差异摘要，二次确认后才写入。
- **恢复默认数据**：二次确认后清除全部本地数据与文件，回到内置默认数据。

> 在另一台设备或另一个浏览器导入后，头像与简历会回落到内置资源，需要重新上传。
> 这是本版本明确接受的限制。数据未加密，清空浏览器数据会导致内容丢失，建议定期导出备份。

## 7. 部署到 Cloudflare Pages

| 配置项   | 值                                            |
| -------- | --------------------------------------------- |
| 构建命令 | `npm run build`                               |
| 输出目录 | `dist`                                        |
| 环境变量 | `NODE_VERSION` = `24`（与 `.nvmrc` 一致）     |
| 包管理器 | npm（已提交 `package-lock.json`，可复现构建） |

仓库的 `public/_redirects` 与 `public/_headers` 会原样拷贝到 `dist/`，由 Cloudflare Pages 读取：

- `_redirects`：只保留说明性注释。SPA 深链由 Cloudflare Pages 的默认行为完成（项目不含顶层 `404.html`，未匹配到静态文件的路径由根路径渲染），刷新 `/projects/<slug>`、`/blog/<slug>`、`/admin/settings` 等深链不会 404。原先的 `/*    /index.html   200` 会被 Wrangler 判定为无效规则并忽略，已移除。
- `_headers`：`nosniff`、`Referrer-Policy`、`X-Frame-Options`、`Permissions-Policy` 与严格的 CSP。
  CSP 保持 `script-src 'self'`、`style-src 'self'`（不含 `'unsafe-inline'`），`blob:` 只开放在
  `img-src`、`object-src`、`frame-src` 三项，用于头像预览与简历内嵌预览。

### 本地验证深链与响应头

`npm run preview` 不会读取 `_headers`，也不会复现 Pages 的 SPA 回落，必须用 Wrangler 模拟 Pages 的行为：

```bash
npm run build
npx wrangler pages dev dist
```

部署后建议逐项确认：深链刷新不出现 404、头像上传后刷新仍能显示、简历预览与下载可用、
浏览器控制台无 CSP 违规报错。

## 8. 无障碍与响应式

- 语义化标签、跳过导航链接（"跳到主要内容"）、不跳级的标题层级。
- 全部可交互元素支持键盘操作，焦点环为 2px 香槟金并带外偏移；弹窗与抽屉关闭后焦点回到触发元素。
- 表单字段带标签、错误文案通过无障碍属性关联，错误出现时以礼貌级别实时区域播报。
- 遵守 `prefers-reduced-motion`：开启后停用星空动画与位移过渡。
- 对比度按 WCAG 2.1 AA 核对：正文与交互文字 ≥ 4.5:1，非文本指示 ≥ 3:1。色值与实测结论记录在 `PRD.md` §8.2 与 §8.4。
- 在 375px、768px、1440px 三档宽度下均无横向滚动与元素重叠；触控目标不小于 44×44px。

## 9. 项目结构

```
src/
├─ app/            路由表、Provider 组合、ErrorBoundary
├─ layouts/        前台与后台框架、响应式导航、页脚
├─ content/        运行时状态层（ContentProvider / reducer / useContent / selectors）
├─ data/           内置默认数据（含 Markdown + frontmatter 文章）
├─ lib/
│  ├─ schema/      Zod schema（数据类型的唯一来源）
│  ├─ storage/     localStorage、IndexedDB、会话、导出导入
│  ├─ markdown/    Markdown 渲染配置、frontmatter 解析、阅读时长
│  └─ *.ts         slug、日期、文件校验、差异计算等纯函数
├─ hooks/          useForm、useAssetUrl、useFocusTrap、提示与确认等
├─ components/     跨 feature 复用组件（含 ui/ 基础组件）
└─ features/       按页面拆分：home、projects、blog、admin、not-found
public/            静态资源、_redirects、_headers
```

数据只在 `src/lib/storage/` 与 `src/content/ContentProvider.tsx` 中读写，其余模块统一通过
`useContent()` 访问，避免绕过状态层直接操作浏览器存储。

## 10. 已知限制

| 限制                 | 说明                                                       |
| -------------------- | ---------------------------------------------------------- |
| 数据仅存于当前浏览器 | 更换设备、浏览器或清空缓存都会丢失，需依赖导出的 JSON 备份 |
| 导出不含二进制文件   | 导入后需重新上传头像与简历                                 |
| 演示登录无真实鉴权   | 任何人都能进入后台，需要真实后端才能解决，超出本项目边界   |
| 项目卡片无封面图     | 以文字排版为主；后续可复用头像的 IndexedDB 方案扩展        |
| 无端到端测试         | 当前以单元与组件测试为主，Playwright 冒烟用例为可选加分项  |
